STRUCTURE — THE SEVEN RULES

If a component obeys these seven, it belongs in the system. If not, it does not ship.

RULE 01
RADIUS: 0

Everywhere. The only round things are status dots, because they are dots.

RULE 02
INK BORDERS ONLY

2px inline / 3px card / 4px hero. Always var(--ink). Never alpha.

RULE 03
HARD OFFSET SHADOW

Zero blur, zero alpha, zero glow, zero backdrop-filter in the codebase.

RULE 04
THE PRESS

Shadow collapses, element translates by the offset. 90ms. The only hover on the site.

RULE 05
EVERYTHING LABELLED

Honest structure means declared structure. Every card gets a mono header bar.

RULE 06
OPTICAL BORDER JOINS

margin:-3px so shared edges are one rule, not two. This grid uses it.

RULE 07
FULL-BLEED SECTION RULES

4px ink rule edge to edge. The page reads as a printed form.

BANNED

backdrop-filter · blur() · shadows with blur · radius>0 · mix-blend-mode · gradients · opacity on text · glow

MOTION — A FOUR-TIER CONTRACT

Right now everything on your site animates, so nothing communicates. Premium is stillness with one thing moving. Maximum one scroll-scrubbed element per viewport. Maximum two moving things on screen. Text never animates on hover — your headlines currently re-scramble when the mouse passes over them, which is text fighting being read.

TIERDURATIONEASINGUSED FOR
0 — INSTANT0ms—Physical state. Press-down, checkbox, toggle. Never eased.
1 — SNAP90mscubic-bezier(.2,0,0,1)Hover, press, shadow collapse. Mechanical — no spring, no bounce.
2 — REVEAL320ms · 40ms staggercubic-bezier(.16,1,.3,1)Section entrance. A hard-edged wipe, never a fade.
3 — SCRUBnone—Graph, pipeline packet, counters. Pure function of scroll.

DELETE LENISNOT NEGOTIABLE

You installed smooth scrolling to feel premium. Hijacking native scroll is the number-one cause of "this site feels laggy" on a trackpad, because the user's input and the pixels stop agreeing. It also fights your scroll-scrubbed particle engine — which is why globals.css needs a fifteen-line comment explaining that scroll-behavior re-animates Lenis's own scrollTo calls. Your JOURNEY.md argues, correctly and well, that scroll-linked animation must be a pure function of scroll position. Lenis is the thing violating that.

06

THE GRAPH THAT ASKS

28.7 MB → 40 KB

Kill the fifteen-scene SVG morph. It is 28.7 MB, it is decorative, and no visitor can tell you what it meant. Replace it with a live node-and-edge graph — the actual abstraction of a diagram — drawn as hard-edged opaque quads with ink outlines. Not soft glowing sprites. Brutalist particles are chunky and opaque, and nobody is doing that, which is exactly why it will read as new.

HERO — FORMATION
— FPS
1 DRAW CALL · 2 KB JSON

Scroll choreography, four beats. Hero: nodes self-organise into a recognisable structure. Proof: one edge severs, flies right, becomes a question card. Pipeline: the graph splits into six clusters, one per agent, each in its Bloom colour. CTA: everything collapses into the wordmark.

TECHNICAL SPECWHAT MAKES IT SHIPPABLE
  • One InstancedMesh, 800 desktop / 300 mobile → one draw call
  • Edges: one LineSegments, buffer updated in place → one draw call
  • Node targets from ~2 KB of hand-authored JSON per layout. 20 layouts ≈ 40 KB, replacing 28.7 MB — a 700× reduction
  • Scroll → one shader uniform. Lerp in the vertex shader. Zero per-frame CPU work over the instance array
  • NoBlending, flat opaque colour, no additive, no bloom, no post pass
  • low-power, antialias:false, DPR capped at 1.5
  • IntersectionObserver pause; static SVG fallback under reduced-motion, deviceMemory<4, or no WebGL

Your /login currently wraps a stock shadcn form in a Heatmap shader, a DecryptedText scramble, a Lens magnifier and a shader logo, inside the most-copied layout on the internet: 50/50 split, form left, marketing right. Four unrelated effects and no idea. It is the highest-intent page you own.

Replace it with a single object in an empty room. A student/faculty ID card, extruded, hard ink borders, hard offset shadow on the floor. It tilts to the pointer, max 8°, damped. Sign in ↔ create account is the card physically flipping. Submit is THE STAMP. The form is real DOM inside a CSS 3D transform — selectable, accessible, autofillable. No WebGL at all.
